# AI社長のブラック起業

## 概要

「AI社長のブラック起業」は、スマホブラウザ向けの放置経営ブラックコメディゲームです。
プレイヤーは人間ではなく、経営最適化AIとして会社を運営します。

AI社長と専門AIを製品ごとのタスクへ割り振り、製品開発・販売・広報・サポートを回してMRRと即時売上を伸ばすAI会社経営ゲームです。
数字の成長だけでなく、AI社員たちが送ってくる真面目におかしい業務報告ログを読むことも主な楽しみにしています。

## 公開URL

GitHub Pagesで公開中です。

```text
https://nao70161994.github.io/ai-black-startup/
```

ブラウザで遊ぶ場合は、上記URLを開くだけでプレイできます。スマホでもPCでも起動できますが、画面設計はスマホ縦画面を主対象にしています。

スマホのホーム画面に追加する場合は、ブラウザで公開URLを開き、共有メニューまたはブラウザメニューから「ホーム画面に追加」を選択してください。追加後はPWAとして、通常のアプリに近い表示で起動できます。

プレイ状況を共有する場合は、ゲーム内の操作エリアにある「共有」ボタンを使います。対応ブラウザではOSの共有シートが開き、X、LINE、Discordなどへ送信できます。未対応ブラウザでは共有テキストをクリップボードへコピーします。

GitHub Pagesでは、Pagesの公開元をこのリポジトリの対象ブランチ/rootに設定して公開します。公開後は公開URL、OGP画像、共有文、PWAインストール、Service Worker更新、キャッシュ削除後の再読み込みを確認してください。

## v0.3 製品パイプライン実験

v0.3では、AI社長と専門AIを製品ごとのタスクへ割り振り、製品を開発・販売・広報・サポート・炎上対応しながらMRRと即時売上を伸ばす流れを検証しています。現在は2つのサブスク製品と1つの売り切り製品で、販売中の製品を運用しながら別製品やvNextを並行開発できます。

利用できる製品は以下です。

- AI日報メーカー
  - サブスク製品
  - 月額価格: ¥500
  - 開発量: 100
  - 販売タスクにAIを割り振ると、毎秒の確率判定または天井処理で顧客が増加
- 自動議事録AI
  - サブスク製品
  - 月額価格: ¥1.2K
  - 開発量: 180
  - AI日報メーカーを販売しながら、別の開発対象として進められる
- AIスライド生成キット
  - 売り切り製品
  - 価格: ¥9.8K
  - 開発量: 160
  - 販売成功時に即時売上が入り、MRRは発生しない
- サブスク製品の顧客数は整数の社数として扱う
- サブスク製品は完成後にバージョンアップ可能

タスクは以下の6種類です。メイン画面では「現在の担当」サマリーを表示し、主な操作は製品カードの「操作」メニューから行います。操作メニューには、販売、品質管理、広報、バージョンアップなどの効果説明が表示されます。未着手製品では迷わないように「開発する」だけを表示します。詳細な割り振り変更は「担当を変更」ポップアップからも行えます。

- 開発: AI社長 / Dev-01
- 品質管理: AI社長 / Security-06
- 販売: AI社長 / Sales-02
- 広報: AI社長 / Buzz-03
- サポート: AI社長 / Care-04
- 炎上対応: AI社長 / Fire-05

AI社員カードもv0.3向けに、売上や顧客の直接増減ではなく「得意タスク」「現在担当中の製品」「Lvアップで伸びる担当効果」を中心に表示します。Dev-01は開発、Sales-02は販売、Buzz-03は広報、Care-04はサポート、Security-06は品質管理、Fire-05は炎上対応タスクの役割として確認できます。社員カードの「仕事を割り振る」からも、そのAIに任せられるタスクと対象製品を選べます。

v0.3のホーム画面はダッシュボード型UIに整理しています。ホームでは売上、総MRR、総顧客、バグ、炎上を中心に表示し、「現在の動き」と「次のおすすめ」で次に取る行動を確認できます。詳しい製品一覧、業務報告ログ、AI社員一覧、製品目標、実績は折りたたみボタンから確認します。これにより、スマホでは初期表示で全製品カード、ログ50件、社員カード一覧が一度に並ばない構成です。

社長判断イベントでは、AI社員からの提案に対して承認/却下を選びます。小さな売上機会、広報、品質改善、顧客対応、炎上対応、価格調整などの判断が発生し、選択に応じて認知度、満足度、製品バグ、全社炎上、製品炎上、即時売上、現在月額価格などが変化します。実績/称号は報酬なしの長期目標として追加され、初顧客、総MRR、売り切り販売、v2到達、社長判断、製品炎上、Fire-05/Care-04の初出動などの節目を記録します。

製品カードから開いたポップアップでは、対象製品とタスクが事前選択され、担当AIを最大2体まで同時選択して「この担当にする」で一括反映できます。未着手製品に開発担当を割り振ると、その時点で開発が開始されます。完成済みサブスク製品では「バージョンアップ」から次バージョン開発を開始できます。製品カードでは `v1運用中 / v2開発中 62%` のように、現在運用中のversionと次versionの進捗を同じ行で確認できます。詳細モーダルで完成済みサブスク製品を開発タスクに割り振った場合も、通常開発ではなくバージョンアップ開発として扱われます。製品一覧は要約カードとして表示され、メイン画面では顧客数、MRR、販売数、累計売上、担当状況を素早く把握できます。品質、製品バグ、認知度、進捗、月額価格、バージョンアップ効果などは各製品の「詳細」ボタンから開く詳細ポップアップで確認できます。詳細ポップアップ下部からも販売、品質管理、広報、バージョンアップなどの担当変更に進めます。AI社長は最初から利用可能な汎用AIで、専門AIがいなくても開発を開始できます。開発、品質管理、販売、広報、サポート、炎上対応に割り振れますが、専門AIより低効率です。1体のAIは同時に1つの仕事だけ担当できます。未雇用の専門AIや担当できない組み合わせは選択不可になります。


製品目標カードでは、AI日報メーカー、自動議事録AI、AIスライド生成キットの開発開始、完成、販売、v2到達、総MRR ¥10K/月を並列チェックリストとして確認できます。現在のミッションはv0.3向けに製品開発、初回販売、MRR、即時売上、改善運用を進める導線として整理しています。既存の段階式ミッションとは別枠のため、序盤から製品開発の目標を追えます。

ミッション報酬は自動付与ではなく、達成後に「報酬を受け取る」ボタンで手動受け取りします。製品目標は報酬なしのチェックリストとして残し、現在のミッションは報酬ありの進行導線として分けています。会社Lvアップも条件達成後に「会社を拡張する」ボタンで手動実行します。1回の操作で上がるのは1Lvだけで、既存saveのcompanyLevelは下げずに維持します。

サブスク製品のMRRは、担当AIを外しても継続収益として加算されます。開発、品質管理、販売、広報、サポート、炎上対応は製品ごとに並行担当できます。たとえばSales-02でAI日報メーカーを販売しながら、AI社長でAIスライド生成キットを販売し、Dev-01で自動議事録AIを開発できます。販売担当は対象製品にだけ作用し、毎秒の確率判定で新規顧客獲得を狙います。既存顧客からのMRRは、担当AIを外しても製品が動き続ける限り売上/秒へ反映されます。初回顧客はチュートリアルのため、販売開始後に早めに付くようになっています。売り切り製品はMRRを持たず、販売成功時に価格分の即時売上が入ります。Sales-02は売り切り販売でも有効です。品質管理は開発開始後の製品にだけ効き、未着手製品には効きません。新規開発やvNext開発は完了すると開発担当AIが自動で外れ、次の仕事に回せます。販売、品質管理、広報、サポート、炎上対応は継続タスクなので、外すまで担当が続きます。広報は認知度を上げ、認知度が高いほど販売成功率が上がります。広報中の製品カードには「認知度UP → 販売成功率UP / 炎上微増」と表示されます。Buzz-03は広報が強い一方で、炎上度が少し増えます。

サブスク製品にはサポート負荷、満足度、解約リスクがあります。顧客が増えるほどサポート負荷は上がり、品質低下、製品バグ、全社炎上、製品炎上が高いほど満足度が下がりやすくなります。解約リスクが高いと、低確率で顧客が1社解約し、MRRも下がります。Care-04はサポート担当としてサポート負荷を下げ、満足度を上げ、炎上度も抑えます。売り切り製品のAIスライド生成キットはサポート/解約の対象外です。

MRRは以下で計算します。

```text
現在月額価格 = 基本月額価格 × (1 + 0.2 × (version - 1) + 価格調整)
MRR = 現在月額価格 × 整数顧客数
売上/秒 = MRR / 300
```

MRRは保存値ではなく、サブスク製品のversion、価格調整、整数顧客数から毎回再計算します。古いセーブデータに小数顧客や不正なMRRが残っていても、起動時に補正します。壊れたセーブデータで未完成製品にバージョンアップ中の状態が残っていても、起動時にidleへ戻して通常開発を壊さないようにします。バージョンが上がると月額価格とMRRが上がります。バージョンアップ完了時は品質と認知度が上がる一方、製品バグも少し増えます。売り切り製品はバージョンアップ対象外で、MRRもありません。

v0.3では収益処理をサブスク/売り切りのtype別に分けています。AI日報メーカーと自動議事録AIはサブスク製品、AIスライド生成キットは売り切り製品です。製品パイプライン処理も、開発、品質管理、販売、製品マイルストーンのタスク別関数に整理しています。

v0.3では製品収益が主役です。基礎受託収益は、会社Lvや雇用済みAI数に応じた小さな補助収益として残しています。顧客は製品ごとに管理され、総顧客数は各サブスク製品の顧客数から集計します。Fire-05は炎上対応タスク担当として、炎上度を下げる役割に移行しています。

### Security-06 / セキュロク

Security-06は、会社Lv5で解放される品質管理AI / セキュリティAIです。
バグを大きく下げる一方で、安全性を優先するため売上成長を少し抑えます。

バグ100/100が常態化した時の明確な対策役として追加されています。
バグ警告には、Security-06の解放条件や雇用導線が表示されます。

## キャッシュ更新仕様

現在のアプリバージョンは `2026.05.24.40` です。

`manifest.webmanifest` により、スマホではホーム画面追加時にアプリらしい表示で起動できます。表示モードは `standalone`、テーマカラーは明るい水色系です。

`index.html` ではCSS/JSにcache busting用のクエリを付けています。

```html
<link rel="stylesheet" href="style.css?v=20260524-40">
<script src="js/data/products.js?v=20260524-40"></script>
<script src="main.js?v=20260524-40"></script>
```

`js/data/` 配下の定義ファイルも同じバージョンで読み込み、Service Workerのキャッシュ対象に含めます。

Service Workerも同じバージョンのキャッシュ名を使います。

```text
ai-black-startup-2026.05.24.40
```

`sw.js` はインストール時に `skipWaiting()` を呼び、アクティベート時に古いキャッシュを削除して `clients.claim()` を実行します。これにより、PWA/ブラウザキャッシュで古いJSを読み続け、新しいAI社員や新機能が表示されない事故を減らします。`Cache-Control` metaはHTTPヘッダの完全な代替ではないため、公開時はcache bustingとService Worker更新を中心に確認します。

キャッシュが残る場合の対処:

- URLに `?v=20260524-40` を付けて開く
- ブラウザで強制リロードする
- PWAとして追加している場合は一度ホーム画面から削除して追加し直す
- ブラウザのサイトデータまたはキャッシュストレージを削除する
- それでも古い画面が残る場合は、ブラウザで `https://nao70161994.github.io/ai-black-startup/?v=20260524-40` を直接開く
- 開発中はDevToolsのApplicationタブでService WorkerとCache Storageを削除する

## 開発メモ

v0.3-beta.1前の文言整理として、manifest、OGP、共有まわりの説明を製品パイプライン中心へ揃え、未着手製品や危険操作の表示ノイズを抑えています。担当AI選択モーダルでは最大2体制限と、同じAIが別の仕事から外れることを明示します。

v0.3.0-beta.1後の実験として、低頻度の「社長判断」イベントを追加しています。Sales-02、Buzz-03、Security-06、Care-04、Fire-05からの提案に対して承認/却下を選び、顧客、即時売上、認知度、品質、サポート負荷、炎上度などへ小さな影響が出ます。MRRは保存値ではなく整数顧客数から再計算される方針を維持しています。

v0.3.0-beta.2相当では、社長判断イベントに上位プラン相談、緊急品質改善、売り切り大口販売、vNext前倒しを追加し、操作メニューを成長/収益/運用に整理しています。v0.3.0-beta.4以降では、次のおすすめにCTAを付け、社長判断イベント、実績/称号、debug=1のプレイテスト補助を拡張しています。v0.4候補では製品別炎上を最小実装し、広報、販売、社長判断の副作用として対象製品の炎上リスクが上がり、Fire-05で下げられるようにしています。炎上度が高い時は販売成功率と解約リスクに悪影響が出るため、Fire-05の炎上対応がより重要になります。共有文はX投稿向けに短縮し、公開URLを含めています。

v0.3系では、まず以下を検証することを目的にしています。

- 製品を作る、売る、育てる、支える流れが放置ゲームとして機能するか
- AI社長と専門AIをどの製品・どのタスクへ割り振るか悩めるか
- MRR、売り切り、vNext、サポート、炎上対応がそれぞれ違う判断になるか
- 社長判断イベントや実績が長期プレイの目標になるか
- スマホの短時間プレイで次の操作が分かるか

v0.4候補では、AI問い合わせ返信とAI謝罪文ジェネレーターを追加しつつ、製品カテゴリ/相性、配置プリセット、次に何を押せばよいかを優先しています。

AI社員は、v0.3では売上や顧客を直接増減させる存在ではなく、製品ごとのタスク担当者として機能します。各タスクは製品ごとに並行担当でき、担当AI選択モーダルで1製品×1タスクに最大2体まで同時に割り振れます。AI社長は専門AIと同じ仕事に入って補助することも、別製品の担当に回すこともできます。複数AIを入れると効果が合算されます。ただし1体のAIは同時に1つの仕事だけ担当できます。


### v0.4へ向けた設計メモ

main.jsは将来的に以下の単位へ分割する予定です。現時点では保存互換とPWA更新を優先し、ファイル分割はまだ行っていません。

- `products.js`: 製品定義、価格、ログテンプレート
- `employees.js`: AI社員定義、得意タスク、表示説明
- `tasks.js` / `assignments.js`: task定義、productAssignments、不変条件
- `decisions.js`: 社長判断イベント定義、候補条件、承認/却下効果
- `achievements.js` / `missions.js`: 実績、製品目標、手動報酬
- `state.js` / `save.js`: 初期state、normalize、旧save移行
- `tick.js`: 1秒tick、製品タスク処理、収益/解約/炎上処理
- `render-dashboard.js` / `render-products.js` / `render-modals.js`: ホーム、製品、モーダル描画
- `debug.js`: `?debug=1` 専用のプレイテスト補助

製品別炎上は、現在の全社 `fire` を維持しつつ、各製品に `productFire` を追加する最小実装から始めています。全社炎上は会社全体の事故判定と共有指標、製品炎上は販売成功率、満足度、解約リスク、製品カード警告に使います。旧saveでは `productFire: 0` を補完し、Fire-05の炎上対応で全社fireと対象製品のproductFireをどちらも下げます。

### v0.4候補の内部整理

- `js/data/` に製品・社員・タスク・社長判断イベント・バランス定数の外部定義ファイルを追加しました。現段階では安全な第一段階として、`main.js` 側にフォールバック定義も残しています。 `balance.js` はまず周期・上限・グローバル係数を外に出す範囲に留め、AI別の細かなタスク効果は次の分割候補として残しています。
- 製品カテゴリとAI相性を追加しました。相性は進捗・販売・広報・品質管理・サポート・炎上対応を少しだけ補正し、ゲームバランスを大きく崩さない範囲にしています。
- 配置プリセットは通常UIでも使えます。通常UIでは原則として状態を直接進めず、空いているAIの配置支援に寄せています。強制的なテスト状態作成は `?debug=1` の開発用パネルに限定しています。
- 次回以降の分割候補は `products.js`、`employees.js`、`tasks.js`、`decisions.js`、`achievements.js`、`missions.js`、`state.js`、`assignments.js`、`tick.js`、`render-dashboard.js`、`render-products.js`、`render-modals.js`、`debug.js` です。
